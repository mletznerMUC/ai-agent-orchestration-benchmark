## Observation A — decides `multi-agent-parallel`

**Inputs.** Two `ToolLoopAgent` instances, each with its own scripted mock
model and its own `work` tool. Agent A's model takes 60 ms per step, agent B's
20 ms, and the tool takes 40 ms in both. Both are started together with
`Promise.all` and bounded by `stopWhen: isStepCount(4)`.

**What was observed.** Both loops ran at the same time in one Node process.
Agent B started its model call 1 ms after agent A, executed its tool at
t+58 ms while agent A was still waiting on its first model call, and finished
its whole two-step loop at t+121 ms — 78 ms before agent A finished at
t+199 ms. Six of agent B's recorded events fall inside agent A's active
window. Each agent completed a two-step loop (tool call, then final text) and
returned its own distinct answer, so neither run was starved or serialised
behind the other.

**What this does not show.** The AI SDK provides no scheduler, queue or worker
pool here. The concurrency is the host program's: `Promise.all` over two
`generate()` calls, which is the pattern the documentation itself shows for
parallel work. What the observation establishes is that the agent loop is
re-entrant and non-blocking enough for that pattern to actually interleave,
which is what the documentation left open.

**State this supports:** `multi-agent-parallel` = `yes`, label "Subagents",
tier C.

## Observation B — corroborates `group-chat` (not decisive)

**Inputs.** A parent `ToolLoopAgent` whose `research` tool calls
`subagent.generate()` and returns the subagent's text as the tool result.

**What was observed.** The parent's tool call delegated at t+213 ms, the
subagent ran its own two-step loop, and its text
`subagent summary: two facts found` came back into the parent as the tool
result before the parent produced its final answer. Communication was
one-directional: parent → subagent → result. Nothing in the run shows two
agents conversing as peers.

**State this supports:** `group-chat` = `partial`. The cell is scored tier B
from `https://ai-sdk.dev/docs/agents/subagents`, which already settles it;
this observation only confirms the documented shape of the delegation.

## Observation C — corroborates `hitl` (not decisive)

**Inputs.** One agent with a `deleteFile` tool and
`toolApproval: { deleteFile: 'user-approval' }`. The tool's `execute` logs an
`EXECUTED` line if it ever runs.

**What was observed.** The loop stopped after the first model step with one
`tool-approval-request` content part and no `EXECUTED` line, so the tool did
not run. `tool executed without approval: false`.

**State this supports:** `hitl` = `yes`. The cell is scored tier B from
`https://ai-sdk.dev/docs/agents/tool-approvals`; this observation only
confirms that the documented pause happens.
