# Refresh round 2026-09

Run date: 2026-09-02. Twelve researchers (one per tool key in
`data/tools.json`) and one scout ran in parallel; all thirteen reported.
Every tool in the benchmark was checked. Market scouting was on.

Maturity criteria were re-derived against the trailing-90-day window
**2026-06-04 → 2026-09-02**, which is three weeks further forward than the
window the 2026-08 round used. Several evidence strings changed for that
reason alone.

`data/tools.json` was written. `index.html` and `index.en.html` were not
touched, so `npm run verify` is expected to be **red** until the change is
approved and `apply.yml` writes the pages — that red is the gate described
in ADR-003, not a defect. `npm run verify` could not be executed in this
environment (node execution was blocked), so the arithmetic below was
checked by hand against the rubric in ADR-005; the verifier is the
authority on it.

**One published score moved: n8n 83 → 86.** One criterion changed without
moving a published score (Databricks). Everything else is evidence,
citation and date refreshes.

**Criterion named:** `mcp-support`, which ADR-005 assigns to dimension 3
(Integration & interoperability, weight 15). The n8n 2.34 release notes
(2026-08-04) record that "instance-level MCP settings are now generally
available. The 'preview' label has been removed"; the MCP Client node and
MCP Server Trigger node doc pages carry no status label today. The cell
was `partial` *because* its label said "Beta" — the vendor removing that
label is what moves it, so the state change follows mechanically rather
than by re-judgement.

Arithmetic: 12.5 + 20.0 + 15.0 + 15.0 + 8.3333 + 15.0 = 85.8333 → 86.

`meta.toolOrder.scores` was resequenced to keep the score grid descending
(n8n now sits above ms-agent and maestro). No other ordering changed.

The researcher confirmed the fact but explicitly declined to set the state,
saying it could not see the rubric-to-matrix mapping. The mapping is
published in ADR-005 and the triage applied it; if the human disagrees that
"preview label removed" equals full support, reverting the cell to
`partial` returns the score to 83.

## 4. Source disagreements

Surfaced, not resolved.

1. **Databricks cadence: what counts as one "release"?** The 2026-08 round
   counted monthly release-note pages and got 3. This round counted
   individually dated entries within those pages and got dozens. Same
   source, different unit, opposite side of the ≥ 6 threshold. Two things
   cut against the new count: it measures the whole Databricks platform's
   cadence, not Agent Bricks specifically, and most entries in it concern
   unrelated features. Two things cut for it: Databricks ships no versioned
   package, so the ADR-005 amendment's "dated platform release notes" is
   the only available analogue, and counting months structurally caps any
   SaaS vendor at 3. **This needs a ruling that applies to every
   continuously-deployed tool, not just this one.** Score impact if
   rejected: Databricks 73 → 71.
2. **ms-agent vs databricks ga-status, applied inconsistently?**
   Microsoft's Go SDK is marked public preview and ms-agent keeps
   ga-status 2; Databricks' supervisor page is marked Beta and drops to 1.
   The distinction drawn was that the scored .NET and Python lines are GA
   while Go is an extra, whereas the Databricks Beta sits on the primary
   product surface. That is a judgement call, not a rule ADR-005 states.
   CLAUDE.md rule 2 argues for writing the rule down.
3. **LangSmith Plus currency.** The site shows "~€39/Mo." / "~€39/mo.";
   the vendor publishes **$39** per seat per month, plus usage-based
   charges. Same digits, different currency. The row is unsourced and was
   not changed, but the € is not what the vendor charges.
   Source: https://www.langchain.com/pricing
4. **Manus ownership.** Three major outlets report a Meta acquisition;
   the vendor's own site says nothing. Unresolved above.
5. **Strands repository identity.** `strands-agents/sdk-python` and
   `strands-agents/harness-sdk` both resolve. Verified as a rename by the
   orchestrator, not merely accepted from the researcher.
6. **Langflow release date (scout).** One automated fetch of the releases
   page read the year as 2024, another as 2026. The 2026 reading is the
   only one consistent with the dated 1.9/1.10 blog posts, but the
   discrepancy is recorded rather than hidden.
